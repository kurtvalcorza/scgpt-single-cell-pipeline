#### Description

`tdc/scGPT` is the *whole-human* scGPT encoder (Cui, Wang, Maan et al., Nature Methods 21:1470–1480, 2024; pretrained on 33 million normal human cells) as repackaged in safetensors by Therapeutics Data Commons (Velez-Arce et al., 2024), pinned here to revision `acf749f35bf5c0b00633838f02588272ed0d9911`. The pinned `config.json` names 12 post-norm transformer encoder layers of width 512 with 8 heads and a 512-wide feed-forward, a 60,697-token gene vocabulary, continuous value embedding, `<cls>` cell pooling and a 1,536-position input; the safetensors file holds 50,804,225 parameters, 31,076,864 of them in the gene-token embedding. A cell enters the model as a set of (gene token, expression bin) pairs — each detected gene's expression quantile-binned within the cell into 51 levels after total-count normalisation and log1p — preceded by a `<cls>` token; the model has no positional encoding, so the cell embedding is invariant to gene order. The packaged checkpoint keeps the gene encoder, the continuous value encoder, the transformer and the masked-expression decoder from the original, and drops the original's 177-class `cls_decoder`, its `mvc_decoder` and its `flag_encoder` (14 tensors; the other 159 are bit-identical to the original `.bin` the packager also ships).

What this repository adds is the `ScGPTPipeline` class in `src/scgpt_single_cell_pipeline/pipeline.py`: manifest verification of the 4-file snapshot before any model library is imported (`verify_snapshot`, refusing a manifest that omits the config, the weights or the vocabulary), fresh-clone staging that fetches Hub files at the pinned revision and the vocabulary from its persistent Harvard Dataverse file id with an immutable exact-byte mirror fallback (`stage_missing_files`), a **re-implementation of the encoder on `torch.nn.TransformerEncoder` and three small blocks** whose parameter names match the checkpoint so it loads with `strict=True` (`build_model`), a gene vocabulary that resolves symbols case-insensitively and reports unknowns rather than mapping them onto a real gene (`load_gene_vocabulary`, `GeneVocabulary`), scGPT's per-cell quantile binning with the seeded tie spread the checkpoint was trained on (`bin_expression`), cell validation with named ceilings (`validate_inputs`), `<cls>` cell embeddings (`embed`), two probes of the pretraining objective (`predict_masked`, `predict_masked_genes`), a zero-training nearest-centroid classifier on centred frozen embeddings (`nearest_centroid_evaluate`), bounded gradient fine-tuning of a linear head plus the last *n* encoder layers (`adapt`), held-out metrics (`evaluate`), argmax classification with per-class scores (`classify`), and a safetensors adapter artifact that is digest-verified before deserialization (`save_artifact`, `from_artifact`).

Three things about this row are stated rather than hidden. **The packager's own loader is not used.** It lives in the PyTDC package with transformers and flash-attention as dependencies, omits the ReLU inside the value encoder that the original scGPT has, feeds raw rather than binned values in its example, maps unknown gene symbols to token 0 (the gene A1BG), and its example passes the attention mask with inverted polarity; this repository follows the original `model.py` and `preprocess.py` instead and depends on torch, safetensors, numpy and huggingface-hub only. **The gene vocabulary is not in the Hub repository:** the manifest lists it as a fourth entry with its Dataverse source and SHA-256 (`docs/WEIGHTS.md`). **The masked-expression decoder is near-constant as shipped:** on 32 real PBMC cells its predictions correlated with the expected bins at Pearson 0.41 while sitting in a band around bins 26–32, and masking a lineage's marker genes in a cell of that lineage versus the other produced no difference in the predicted bin — so a DIMER profile should expose embeddings and classification, not imputation, and the tutorial shows the numbers rather than skipping the question.

#### Intended Use and Limitations

###### Primary Intended Uses

Three tasks are exposed. **Cell representation:** input is 1 to `MAX_CELLS_PER_CALL = 32` cells, each a `{gene symbol: count}` mapping with at least 10 detected genes that resolve to the vocabulary and at most 1,535 kept after truncation; output is one 512-dimensional `<cls>` vector per cell, suitable as features for a downstream model, for nearest-neighbour or centroid classification after centring, or for clustering. **Masked-expression probing:** `predict_masked` and `predict_masked_genes` run the pretraining objective and report predicted against true bins — exposed so that the decoder's behaviour can be measured on the operator's own data, not because it imputes well on ours. **Cell-state classification with local labels:** given a labelled dataset of `{id, counts, label}` records with 2 to 20 classes, the pipeline fine-tunes a linear head over the `<cls>` output, optionally with the last encoder layers, and predicts a class with per-class scores. Envisioned application domains are single-cell workflows where a labelled set exists — annotating cell states in a new experiment from a few dozen labelled cells, transferring a cell-type classifier within a tissue, screening a dataset for a state of interest before deeper analysis, and teaching or evaluating single-cell foundation-model transfer beside Geneformer. In a larger system the pipeline is a feature extractor and a fine-tuning baseline whose output feeds an analyst's review, not an autonomous annotation service. Multi-batch integration — the fleet inventory's nominated first contract for this row — is **not** implemented here; see *DIMER deployment notes*.

###### Primary Intended Users

Intended users are computational biologists, single-cell analysts and machine-learning engineers working with scRNA-seq count matrices, in research, internal enterprise, or the DIMER model workbench. The pipeline assumes its users understand that a pretrained single-cell model encodes co-expression statistics from its corpus, not the biology of their experiment; that cells from one donor, plate or batch belong together and a random split leaks across them (grouped splitting is their responsibility — the pipeline cannot detect batch structure); that the vocabulary is HGNC gene symbols matched case-insensitively, so Ensembl ids and other nomenclatures are dropped and reported, and the input manifest must be read before an embedding is trusted; that binning is rank-based within a cell, so raw and normalised counts give the same tokens but a badly filtered cell still enters; that the softmax scores are uncalibrated; and that the pretrained decoder does not impute usefully on the data we tried.

###### Out-of-scope use cases

1. **Capability boundary:** the pipeline exposes `<cls>` embeddings, two masked-expression probes and supervised classification only. It does not perform multi-batch or multi-omic integration, batch-correction scoring, perturbation-response prediction, gene-network inference, imputation as a product, the published scGPT benchmarks, or any of the organ-specific scGPT checkpoints; it does not read AnnData `.h5ad` files, and it does not verify that a symbol is a real gene beyond vocabulary membership.
2. **Input boundary:** cells are `{gene symbol: count}` mappings of finite non-negative numbers with at least 10 detected genes and at least 10 that resolve to the 60,697-symbol vocabulary; more than 1,535 detected genes keep the most expressed and report the truncation; at most 32 cells per call; a dataset needs at least 8 records, at least 3 per class, at most 2,000 records and at most 20 classes, with unique ids. Protein, ATAC, spatial coordinates, non-human genes and Ensembl ids are not inputs.
3. **Decision boundary:** not for autonomous action on a predicted cell state — diagnostic or prognostic calls, patient stratification, treatment selection, or any use where a wrong annotation has consequences for a person — without task-specific validation on data representative of the deployment's tissue, platform and cohort and expert oversight. A predicted state is a hypothesis for an analyst, not a determination.
4. **Provenance boundary:** not for settings that require numerical parity with the upstream `scgpt` package to have been demonstrated, because it has not been; the evidence here is a strict weight load, bit-identity with the original checkpoint, and functional separation of real lineages.

#### Factors

###### Groups

The pipeline's inputs are gene-expression profiles of cells, not records about people, so age, gender, skin type and socioeconomic status are not attributes of any input and no demographic evaluation applies to the cells themselves. Two human-related factors nonetheless exist. Single-cell data is usually patient-derived: a count matrix from a biopsy is personal health data, the operator inherits the corresponding obligations, and the pipeline neither detects nor mitigates that. And the pretraining corpus — 33 million cells from CELLxGENE, per the upstream paper — reflects who was sequenced and which tissues, ages, ancestries and disease states are over- or under-represented there; the upstream authors do not publish a per-group breakdown, so the model's behaviour on tissues, developmental stages, ancestries or disease states that are rare in the corpus is unmeasured, and an aggregate accuracy on PBMC lineages — which is all this repository measured — says nothing about them. The relevant technical factors are the sequencing platform and chemistry (10x versus plate-based versus nuclei), depth, cell-quality filtering, and gene nomenclature, all of which change which genes are detected and therefore what the model sees.

###### Instrumentation

There is no physical sensor in this pipeline: its input is a count vector, and the instruments that matter are the sequencing platform, the alignment and quantification pipeline, the cell-calling and quality filters, and the gene annotation that produced the symbols. Different platforms detect different numbers of genes per cell (the sample's 348 is far below a typical 10x cell's ~1,000–3,000 and far below the 1,535-token ceiling), different annotations spell symbols differently (HGNC updates, aliases, Ensembl ids), and different filters admit different amounts of ambient RNA and doublets — all of which pass straight into the (gene, bin) tokens. The labels are the second instrument: whether a cell state comes from marker-based annotation, a reference-mapping tool, or a curated atlas, that provenance and its error rate pass directly into the fine-tuned head. At inference the pipeline passes the caller's counts verbatim, normalises and bins within the cell, and detects only the shape errors it validates — types, finiteness, minimum detected genes, vocabulary resolution, duplicate ids — none of which is a quality-control check.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `safetensors==0.8.0`, `numpy==2.5.3`, `huggingface-hub==1.32.0` (`pyproject.toml`) — **no transformers, no PyTDC, no flash-attention** — with the loader mapping to CPU and moving the model to `device`, which defaults to `cuda:0` when CUDA is visible. Only float32 is exercised. Verified locally in a dedicated virtual environment on `torch 2.14.0+cpu`; the recorded CPU run is under "Runtime" (snapshot verification 0.1 s, load 1.8 s, 8 cells embedded in 0.3 s, a 4-epoch adaptation of the head and last layer on 36 cells in 21.5 s). The 203 MB weight download and the 1.3 MB vocabulary fetch dominate a fresh runtime. Data environment: the model assumes human scRNA-seq profiles resembling its CELLxGENE pretraining corpus, given as gene symbols. Its representations degrade, without any error, on non-human genes, on unusual platforms, on cells with very few detected genes, and on inputs that are not cells at all. For the classifier the load-bearing assumption is that evaluation cells are independent of training cells; if they share a donor, plate or batch, the reported metrics measure memorisation of that source, and the pipeline cannot detect this for the operator.

#### Metrics

###### Performance Measures

The pipeline reports, exactly as `metrics.classification_metrics` names them: `accuracy`, `macro_f1` (unweighted mean of per-class F1 over classes present in the split), `per_class` precision/recall/F1 with `support` and `predicted` counts, and `auroc` (binary: positive class is the last entry of the class list; multiclass: macro one-vs-rest, from the Mann-Whitney rank statistic with average ranks for ties). Cell-state datasets are almost always imbalanced, so macro-F1 and the per-class rows are the honest headline, and AUROC measures ranking quality independently of the argmax. Three baselines are reported with the same fields. `nearest_centroid_evaluate` is the **frozen embedding's own separability** with no gradient step: centre the `<cls>` vectors on the training mean, fit one centroid per class on the training split only, assign by cosine — the zero-training number every adapted result must be read against. `majority_baseline` predicts the most frequent training class. `library_size_baseline` thresholds on total counts, fitted on the training split; the sample scales every cell to the same total, so it sits at chance by construction. The masked-expression probes report mean absolute error in bins and Pearson correlation between predicted and true bins (`predict_masked`), and predicted versus true mean bin for a named gene set (`predict_masked_genes`); on this checkpoint they are recorded as a negative finding. The embedding stage reports **no** performance measure. The executed CPU run under "Runtime" is sample-sanity evidence on synthetic cells, not a benchmark; **no upstream benchmark number — cell-type annotation, integration or perturbation — is reproduced or claimed in this repository.**

###### Decision thresholds

The default decision rule for `classify` is an `argmax` over `softmax(logits)` — an implicit threshold, and the only one the pipeline applies; `nearest_centroid_evaluate` uses an argmax over cosine similarities. No tuned operating point ships: the full per-class score dictionary is returned alongside the argmax label so a deployment can apply its own rule, and calibrating that rule is the operator's job. In an annotation context the asymmetry usually runs towards "unassigned" being cheaper than a confident wrong label, which argues for a high threshold on the argmax score plus an explicit unassigned outcome for the borderline band; for a screening context — finding rare cells of a state of interest — a permissive threshold plus analyst review is the safer shape. The limits that *were* fixed during development are input-contract limits, not decision thresholds: `MAX_GENES_PER_CELL = 1535`, `MAX_CELLS_PER_CALL = 32`, `MIN_DETECTED_GENES = 10`, and the dataset minimums and maximums. No accuracy acceptance threshold was set, because this repository ships no task for which one would be meaningful.

###### Approaches to uncertainty and variability

Reported metrics come from a **single seeded holdout**: `split_dataset` stratifies by class with an explicit seed (default 42) into train/validation/test, and `evaluate` scores one split once. No cross-validation, bootstrap or repeated-run averaging is performed, and no dispersion is reported — with a 16-cell tutorial test split, any interval would be dominated by the split. A caller who needs one repeats the workflow over seeds, or supplies enough labelled data for k-fold with donor- or batch-aware folds, and owns that design. Sources of run-to-run variability: the sample generator, the split, the head initialisation and training shuffling are seeded through `random.seed` and `torch.manual_seed`/`torch.cuda.manual_seed_all`; **the quantile-binning tie spread is seeded** (`BINNING_SEED = 42`, matching upstream's distribution deterministically); non-deterministic GPU kernel selection and float accumulation order are **not** seed-controlled. Inference is deterministic in the sense that matters: the same batch embedded twice returns identical vectors and shuffling a cell's gene order changes nothing (both asserted in the tutorial, the latter exactly because tokens are ranked before encoding and the model has no positional encoding), while embedding one cell alone versus inside a batch differed by 1.4×10⁻⁶ on CPU — float accumulation order, not stochasticity. The per-class scores are **not calibrated probabilities**, and a caller who needs calibrated confidence must fit a calibrator on held-out labelled data. Embeddings carry no uncertainty estimate of any kind.

#### Ethical considerations and biases

###### Data

Upstream discloses the pretraining data as 33 million normal human cells from the CELLxGENE collection (the paper) and, for the packaging, that the weights were "extracted from base model"; neither the authors nor the packager publishes a per-tissue, per-donor or per-study breakdown of the corpus, and that is where disclosure ends. Single-cell atlases are built from human donors under their own consents; whether any specific study in the pretraining mix carries a reuse restriction, or whether the aggregate could be linked back to an individual, is not established either way by the upstream authors — unknown, not ruled out. This repository distributes code, tests, documentation and the **1.3 MB gene vocabulary** (a symbol-to-id table with no cell data in it, fetched from Harvard Dataverse and digest-verified); it does **not** vendor the weights in Git, and it ships no cell data — the tutorial cells are generated in code from marker-gene lists and a seeded random background, and contain no measurement from any donor. The build-time functional checks used the public 10x Genomics `pbmc3k` matrix (2,700 PBMCs from one healthy donor, distributed by 10x for public use); nothing from it is committed. The operator owns the audit of whatever they submit: a count matrix from a clinical cohort is personal health data, and the hosted-runtime warning in the tutorial exists because pasting a patient-derived matrix into a cloud notebook is the realistic failure mode. Inference is local and transmits nothing, which bounds exposure but discharges none of those obligations.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by anyone. No experimental validation, no regulatory clearance, no external review board and no testing with any specific group has taken place; the evidence in this repository is the offline unit suite (45 tests), one executed CPU run on 64 synthetic cells, and two build-time functional checks on 32–72 public PBMC cells. Use in a sensitive domain is nevertheless foreseeable — cell-state annotation feeds tumour-microenvironment analysis, immune profiling and biomarker discovery — and would be admissible only with task-specific validation on the deployment's own tissue, platform and cohort, donor-aware evaluation, an analyst reviewing every consequential annotation, and whatever regulatory clearance the domain requires. A predicted cell state from this pipeline is a hypothesis to test, never a clinical finding.

###### Mitigations

1. **Supply-chain integrity:** `MODEL_ID` and the 40-hex `MODEL_REVISION` are module constants; `verify_snapshot()` checks `modelId`, `revision`, and the byte size and SHA-256 of all 4 manifest entries before any load and raises on the first mismatch (tests flip a digit, change the revision and delete a file and assert each raises), and refuses a manifest that omits the config, the weights or the vocabulary. `stage_missing_files()` fetches only manifest-listed files absent on disk — Hub files only at `MODEL_REVISION`, the vocabulary from its persistent Dataverse file id with an immutable repository-revision fallback for the identical bytes — only when `allow_download=True`, and refuses a manifest naming another model. The same manifest digest is enforced after either vocabulary source. `.gitattributes` carries `weights/** -text`.
2. **No remote code and no third-party loader:** the encoder is built in this repository from the pinned `config.json`, whose architecture fields are asserted against the package constants before any model library is imported, and the weights load with `strict=True`. Nothing from the Hub, Dataverse or PyPI beyond torch is executed to build the model.
3. **Faithfulness evidence, stated with its limits:** the 159 packaged tensors are bit-identical to the original `.bin` (attention `Wqkv` = `in_proj` layer for layer); the re-implementation follows the original `model.py` including the value-encoder ReLU and clamp that the packager's port drops; the frozen embeddings separate real B/T/monocyte cells at 72/72. Numerical parity with the `scgpt` package was not measured, and the card says so.
4. **Vocabulary integrity:** `load_gene_vocabulary` requires exactly 60,697 entries with ids 0..60696, no gaps or duplicates, and the three special tokens present; unknown symbols are dropped and counted, never mapped to a real gene.
5. **Artifact integrity:** the adapter is safetensors, not a pickle, and `load_artifact` checks the artifact format, the recorded base model id and revision, the class list, and the size and SHA-256 of every listed file **before** deserialising, then refuses any tensor name the classifier architecture does not have.
6. **Input integrity:** `embed`, `predict_masked`, `predict_masked_genes`, `classify` and `validate_inputs` route through one checker, so their acceptance criteria cannot diverge; it rejects non-mapping cells, non-string gene keys, non-numeric, negative, NaN or infinite counts, too few detected genes, too many cells, and id lists that are the wrong length or not unique, and `bin_expression` refuses a cell with no encodable gene. `validate_dataset` additionally rejects missing columns, duplicate ids, fewer than 2 or more than 20 classes, any class with fewer than 3 records and, given the vocabulary, cells with fewer than 10 encodable genes.
7. **Import boundary:** verification and validation run before `torch`, `safetensors` or `huggingface_hub` are imported (fleet RTM-001); `tests/test_import_boundary.py` fails if a rejected request reaches a model library.
8. **Statistical mitigations:** `split_dataset` stratifies by class; the sample equalises library size and detected genes so the trivial baselines sit at chance by construction; a zero-training baseline is reported beside the adapted number; validation metrics are monitoring only and the final epoch is kept rather than the best.
9. **Honest scope:** validation is labelled structural, the decoder's behaviour is measured and reported as a negative, and integration is declared not implemented.

Not implemented, and therefore not claimed: no numerical parity test against the upstream package, no batch-aware splitting, no cell-quality filtering, no doublet or ambient-RNA handling, no calibration, and no applicability-domain estimate.

###### Risks and harms

1. **A re-implementation can be subtly wrong:** the evidence is strict loading, bit-identity with the original weights and functional lineage separation, not a parity test against the upstream package. A divergence that preserved lineage separation but changed finer structure would not have been caught.
2. **Donor/batch leakage inflating every metric:** a random split of cells from one experiment puts the same donor and batch on both sides, turning memorisation into apparent generalisation. Likelihood is high for any real dataset, and neither the model nor this repository can detect it.
3. **Silent vocabulary loss:** Ensembl ids, aliases and non-human symbols are dropped; a cell can enter with 10 encodable genes out of 3,000 and be embedded without complaint. The input manifest reports the count; an operator who does not read it gets embeddings of a fraction of their data.
4. **The decoder read as an imputer:** `predict_masked` exists and returns numbers; on this checkpoint they are near-constant. A pipeline that used them to fill dropouts would fill them with the same bin.
5. **Uncalibrated scores read as probabilities:** a softmax score of 0.92 from a head trained on 36 synthetic cells is a ranking, not a 92 % chance.
6. **Patient data in a hosted runtime:** the realistic confidentiality failure is a count matrix from a clinical cohort pasted into a cloud notebook. Inference is local, but the runtime may not be the operator's.
7. **Corpus bias with no signal:** tissues, ancestries, ages and disease states rare in the pretraining corpus get representations of unmeasured quality, and nothing in the output says so.

###### Use cases

The model must not be used to produce cell-state or cell-type annotations presented as diagnostic, prognostic or otherwise clinical findings, nor to stratify patients or select treatments, without validation on the deployment's own data and clinical oversight; it must not be used to re-identify donors or infer sensitive attributes about the people whose cells were sequenced, nor to process count matrices the operator has no right to process; it must not be used to impute expression values for downstream analysis on the strength of the decoder exposed here, which this card records as uninformative; it must not be used to generate model-derived annotations deposited into public atlases without marking them as predictions, which would pollute the corpora future models train on; and it must not be used in any way that breaches the MIT terms of the upstream weights or the DIMER deployment terms. These prohibitions hold even where the model would produce an accurate answer.

## Input/output contract

- `ScGPTPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)`: stages and verifies the snapshot, asserts the pinned config's architecture fields against the package constants, loads and validates the vocabulary, builds the encoder and loads the safetensors strictly; `device` defaults to `cuda:0` when visible, else `cpu`.
- `embed(cells, *, names=None) -> dict` with `ids`, `embeddings` (one 512-float `<cls>` vector per cell), `dimension`, `pooling`, `unit`, `tokens`, `unknown_genes`, `n_cells`, `model_id`, `model_revision`.
- `predict_masked(cells, *, names=None, mask_fraction=0.15, seed=42) -> dict`: per-cell `masked_positions`, `mean_absolute_error_bins`, `pearson`, mean true and predicted bins; plus `mask_fraction`, `mask_value`, `n_bins`, `note`.
- `predict_masked_genes(cells, genes, *, names=None) -> dict`: mask the named genes in each cell; per-cell and overall `predicted_mean_bin` versus `true_mean_bin`.
- `nearest_centroid_evaluate(train_records, eval_records, *, classes=None) -> dict`: classification metrics of the centred-embedding nearest-centroid rule fitted on the training split, labelled `baseline: "nearest class centroid on centred frozen <cls> embeddings (no training)"`.
- `adapt(train_records, val_records=None, *, classes=None, epochs=4, learning_rate=1e-4, batch_size=8, trainable_layers=1, weight_decay=0.01, seed=42) -> dict`: bounded AdamW fine-tuning; returns the method description, class list, hyperparameters, trainable/total parameter counts, trainable parameter names, split sizes, the selection rule and the per-epoch history. `trainable_layers=0` trains the head alone on embeddings computed once.
- `evaluate(records) -> dict`: `n`, `accuracy`, `macro_f1`, `per_class`, `classes`, `decision_rule`, `auroc`, `auroc_definition`.
- `classify(cells, *, names=None) -> dict` with `predictions` (each `{id, label, score, scores}`), `classes`, `decision_rule`, `n_cells`, `model_id`, `model_revision`, `adaptation`.
- `save_artifact(output_dir, metadata=None) -> Path` writes `adapter.safetensors` + `manifest.json` (format, base model id/revision/licence, `requires_remote_code: false`, class order, tensor names, empty `serving_state_tensors`, file size and SHA-256, adaptation record); `from_artifact(...)` / `load_artifact(...)` verify all of that before deserialising.
- `validate_inputs(cells, vocabulary, *, names=None)` and `validate_dataset(records, *, vocabulary=None, classes=None, min_records=8, min_per_class=3)` return the input and dataset manifests; both raise exactly what the execution path would raise. `bin_expression(counts, vocabulary, *, n_bins=51, target_sum=10000, max_genes=1535, seed=42)` is the shared encoder; `load_gene_vocabulary(path)` and `GeneVocabulary.resolve(symbol)` are the vocabulary primitives; `build_model(config, vocabulary)` is the re-implemented architecture.
- Constants: `EMBSIZE = 512`, `NLAYERS = 12`, `NHEAD = 8`, `D_HID = 512`, `MAX_SEQ_LEN = 1536`, `MAX_GENES_PER_CELL = 1535`, `VOCAB_SIZE = 60697`, `N_BINS = 51`, `TARGET_SUM = 10000.0`, `MASK_VALUE = -1.0`, `VALUE_CLAMP = 512`, `BINNING_SEED = 42`, `MAX_CELLS_PER_CALL = 32`, `MIN_DETECTED_GENES = 10`, `SPECIAL_TOKENS = ("<pad>", "<cls>", "<eoc>")`, `VOCAB_SOURCE_URL`, `ARTIFACT_FORMAT = "org.valcorza.scgpt-single-cell.adapter.v1"`.

**The open question is the contract, not the licence.** The fleet inventory records this row's "initial contract: scRNA-seq integration" and notes that "initial task scope should stay narrow until broader downstream contracts are fixed". This repository built the narrowest scope that yields checkable evidence — embeddings, a zero-training centroid rule and a bounded classifier — and left integration (batch labels, integration metrics such as batch mixing and biological conservation, the upstream `dsbn` machinery which the packaged checkpoint does not carry) for a contract review. The evidence here bears on it: the frozen `<cls>` embedding separates real PBMC lineages with no training, which is the property an integration workflow would build on, and the re-implemented encoder is small enough (50.8 M parameters, 1.8 s to load) to serve on CPU.
