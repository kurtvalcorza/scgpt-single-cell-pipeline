## Two things this tutorial does that the fleet's others do not

**It carries the model architecture itself.** The Hub repository ships no model code, so `build_model()` in the carried `pipeline.py` rebuilds the scGPT encoder on plain torch modules and the weights load with `strict=True`. Nothing from the Hub, Dataverse or PyPI beyond torch is executed to build the model, and `transformers` is not installed at all.

**One manifest entry comes from a second source.** The gene vocabulary is not in the Hub repository; the carried manifest lists it with its Harvard Dataverse file id as `source`, `stage_missing_files` fetches it from there, and `verify_snapshot` checks its digest with the rest. The notebook's header and External access bullet name Dataverse and the mirror; Section 3 prints which source served the vocabulary.

## Conformance notes

- **Standalone carrier and isolated environment (ST1–ST8, RUN1, RUN10, ENV6):** the primary path performs no clone, repository install or repository import, and installs nothing into the notebook kernel. Section 2 writes the package's 4 modules, the stage runner, the hash lock compiled from the `pyproject.toml` pins (`uv pip compile pyproject.toml --python-version 3.12 --python-platform x86_64-manylinux_2_28 --generate-hashes --only-binary :all:`), the 4-file snapshot manifest and `LICENSE` into a run directory and verifies each against its SHA-256; a pinned `uv` wheel builds a managed CPython 3.12.12 environment from the lock with `--require-hashes`, reused per lock digest, and every learner cell runs one stage in its own process (`MPLBACKEND=Agg`, no inherited `PYTHONPATH`/`PYTHONHOME`/`PYTHONSTARTUP`). `metadata.dimer.generated_from` records the repository, the revision, the package SHA-256, the carried-file digests and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried file differs from the repository, when the lock does not pin every runtime pin with hashes, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent — Hub files from the Hugging Face Hub at the immutable revision (never `main`), the vocabulary from its persistent Dataverse file id; `verify_snapshot` re-hashes every entry; `ScGPTPipeline.from_pretrained(weights_dir=...)` then asserts the pinned config against the package constants, validates the vocabulary, builds the encoder and loads the safetensors with `strict=True`. The `scgpt_gh_repo_original_model.bin` pickle is not in the manifest and is never loaded (MOD9); no remote code is executed. The notebook's own cells import no model library; all model work happens in the stage runner, inside the isolated environment.
- **Stages (§4.1):** `weights` (stage + verify) → `data`: `generate_sample_dataset` / `load_byod_dataset` → `validate_dataset` with the vocabulary → `split_dataset` (stratified) → `tokens`: `bin_expression` + `validate_inputs` with refusal and truncation probes (input manifest written) → `embed`: `pipe.embed` with reproducibility, gene-order and batch verdicts → `probe`: `pipe.predict_masked` + `pipe.predict_masked_genes` → `baselines`: `nearest_centroid_evaluate` + `majority_baseline` + `library_size_baseline` (training split only) → `adapt`: `pipe.adapt` (bounded gradient fine-tuning, real on the default path) + `pipe.save_artifact` → `evaluate`: `ScGPTPipeline.from_artifact` in a fresh process, held-out metrics, deltas and an interpretation line → `export`: new-cell inference from a fresh reload with parity against the adapting process → `result`: provenance; optional `activity` (`TRAINABLE_LAYERS`, written to `outputs/activity/`). No stage asserts a quality level; checks print verdicts, and only a broken reload contract stops the run.
- **Score semantics (UNC1–UNC4):** the per-class scores are softmax outputs of a head trained on 36 synthetic cells, **not calibrated probabilities**; the only decision rule is argmax, and deployment thresholding is the caller's. Embeddings are labelled as representations with no intrinsic metric (EVAL9). The masked-expression numbers are labelled as a probe of the shipped decoder and read as a negative result where they are one.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the zero-training nearest-centroid rule, the majority rule and the library-size threshold are computed on the same test split as the adapted model, and every metric is labelled as tutorial sample-sanity evidence from one seeded holdout with no dispersion estimate. The sample equalises library size and detected genes by construction, which is what makes the library-size baseline informative, and builds its classes from real marker programmes, which is what makes the frozen-embedding baseline informative.
- **Split integrity (SPL1–SPL8):** the split is explicit, stratified and seeded; validation metrics are used for per-epoch monitoring only and the final epoch's weights are kept, so the test split is never used for selection. The notebook states that random splitting assumes independent cells and that cells from one donor, plate or batch leak — split by that grouping on real data.
- **Ceilings (VAL6):** `MAX_GENES_PER_CELL = 1535` (truncation to the most expressed, reported), `MAX_CELLS_PER_CALL = 32`, `MIN_DETECTED_GENES = 10`, the vocabulary size and special ids, and the record and class minimums and maximums are printed from the schema and the dataset manifest before the model runs; four rejections and one truncation are demonstrated, and scale invariance of the binning is reported as a verdict.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, `BYOD_PATH` works in any runtime and an empty path opens the Colab dialog (cancelled or multi-file uploads stop with a message; outside Colab the cell names `BYOD_PATH`). Up to `INFERENCE_CELLS` cells are held back before the split, so Section 11 classifies cells outside train, validation and test; user data flows through the same validation, split, baselines, adaptation, evaluation, export and reload stages, and every refusal names the file and the rule. The expected schema, the gene-symbol convention (HGNC symbols, not Ensembl ids) and the privacy guidance — a patient-derived matrix is restricted data — are stated in the Prerequisites and in Section 4, and the dataset is written to `outputs/scgpt_single_cell_dataset.csv` in the genes-as-columns shape as a template.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
